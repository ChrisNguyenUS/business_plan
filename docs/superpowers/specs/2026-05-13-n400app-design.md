# N400 Civics Test App — Design Spec

**Date:** 2026-05-13
**Status:** Draft — pending user review
**Target route:** `mannaos.com/n400app`
**Codebase location:** `apps/website/` (integrated, not standalone)

---

## 1. Problem & Goals

Help Vietnamese-American naturalization applicants prepare for the USCIS 2020/2025 civics test (128 questions, pass = 12/20 correct, fail = 9/20 wrong) through a bilingual, low-friction practice app.

**Primary user:** Vietnamese-speaking adults in Texas (Houston-area focus initially), low tech literacy, preparing for N-400 interview.

**Success criteria:**
- User completes signup + setup + first mock test in one session
- App usable by non-tech users — large fonts, big buttons, clear bilingual labels
- Mock test simulates USCIS interview rules accurately (stop early at 12 correct or 9 wrong)
- Audio pronunciation helps user prepare for English interview
- Lead generation channel for MOS N-400 filing service

**Non-goals (v1):**
- Paid plans / paywall
- Ads
- AI-generated content at runtime
- Email reminders for streak
- Mobile native app

---

## 2. Architecture Overview

**Integration model:** new routes inside existing `apps/website/` Next.js 16 App Router project. Reuse Supabase Auth, i18n (en/vi), admin pattern from Phase 3, layout shell.

**New routes (under `/[locale]/n400app/`):**
1. `/n400app` — landing + dashboard (auth-gated)
2. `/n400app/setup` — first-time location form
3. `/n400app/practice` — Daily Practice
4. `/n400app/mock-test` — Mock Test (interview simulation)
5. `/n400app/flashcards` — Flashcard mode
6. `/n400app/all-questions` — browse all 128

**Admin route:** `/[locale]/admin/n400` — content + location data management.

**Auth:** Supabase Auth (email + Google + Facebook OAuth). All `/n400app/*` routes except landing are auth-gated.

**Data:** Supabase Postgres (DB) + Supabase Storage (audio). Content in DB so admin can edit without redeploy. Aggressive Next.js cache (revalidate 1h + tag-based invalidation on admin edit) to keep page loads fast.

**External dependencies:**
- **Geocodio API** — street address → congressional district (Q29 lookup). Free tier 2,500/day.
- **TTS provider** (one-time generation): ElevenLabs or OpenAI TTS. Output stored in Supabase Storage.

**Disclaimer (footer on all `/n400app/*`):**
> Tài liệu học liệu. Không phải tư vấn pháp lý. Nội dung lấy từ USCIS.gov.
> Study material only. Not legal advice. Content sourced from USCIS.gov.

### 3.3 RLS policies

- `n400_questions`, `n400_answers`, `n400_location_answers`, `n400_state_data`, `n400_representatives`: public read; admin write only.
- `n400_user_profile`: user can read/write own row only.
- `n400_quiz_attempts`, `n400_question_attempts`: user reads/writes own; admin reads all.

### 3.4 Storage

Bucket `n400-audio/`: public read, admin write only.

Layout:
```
n400-audio/
  questions/q001.mp3 ... q128.mp3
  answers/q001-a001.mp3 ...
  reps/{state_code}-{district}.mp3
```

## 4. User Flows

### 4.1 First-time user
1. Visit `mannaos.com/n400app` → landing (bilingual, CTA "Bắt đầu học / Get Started")
2. Click CTA → Supabase Auth login (email / Google / Facebook)
3. After auth → check `n400_user_profile`. If missing → redirect `/n400app/setup`.
4. Setup form:
   - Heading: "Cho biết bạn đang ở đâu / Where do you live?"
   - Helper (bilingual, always visible): *"Vui lòng điền địa chỉ chính xác để app xác định đúng đáp án cho câu hỏi về Hạ nghị sĩ khu vực bạn đang sinh sống. Zipcode đôi khi chồng lên nhiều khu vực bầu cử, nên cần địa chỉ cụ thể. / Please enter your accurate address so we can identify your U.S. Representative. Zipcodes sometimes span multiple districts."*
   - Fields: Street Address, City, State (dropdown 50), Zipcode (5 digit)
   - PII notice: "Địa chỉ chỉ dùng để xác định đại biểu của bạn, không chia sẻ với bên thứ ba."
   - Submit → server action calls Geocodio → save profile with `district_number` → redirect dashboard.
5. Edit profile later via "Đổi địa chỉ" link in dashboard (re-runs Geocodio).

### 4.2 Returning user
- Login → has profile → dashboard `/n400app`.
- Dashboard:
  - Streak card prominent: 🔥 X ngày, longest Y, progress bar to next milestone (3/7/14/30/100)
  - 4 large mode cards: Daily Practice, Mock Test, Flashcards, View All 128
  - Stats: total answered, accuracy %, mock tests passed

### 4.3 Mock Test (core feature)
1. Click Mock Test → confirm modal ("20 câu, cần đúng 12 để pass. Sẵn sàng?") → Start
2. Random pick 20 distinct questions from the eligible pool (128 minus any excluded due to missing location data for user's state — see §5.4)
3. For each question render:
   - Question EN + VI
   - Auto-play question audio on load (Repeat 🔊 button)
   - 4 options = 1 random correct + 3 random distractors (shuffled)
   - Location-based questions: query `n400_location_answers` (Q23/61/62) or `n400_representatives` (Q29) using profile.
4. User selects → immediate feedback:
   - ✓/✗ color + icon
   - Auto-play correct answer audio
   - Show all acceptable correct answers (for multi-correct questions)
   - "Câu tiếp theo" button
5. Stop conditions:
   - 12 correct reached → PASS screen with shareable certificate
   - 9 wrong reached → FAIL screen with breakdown of missed questions
   - Reach 20 without either → final score screen
6. Save `n400_quiz_attempts` (mode=`mock_test`, passed=bool) + per-question rows.

### 4.4 Daily Practice
1. Click Daily Practice → slider 1–20 (default 10) → Start
2. Same render as Mock Test, but no early stop and no pass/fail logic. Run all N questions.
3. Final score + breakdown. Save with mode=`practice`.

### 4.5 Flashcards
1. Click Flashcards → category filter (All / specific) → Start
2. Card UI: front = question EN+VI + auto audio; "Lật thẻ 🔄" reveals all correct answers + audio
3. "Đã thuộc ✓" / "Chưa thuộc ✗" buttons → save as flashcard attempt
4. Navigation: Prev / Next

### 4.6 View All 128
- Accordion grouped by category
- Search box (matches question_en + question_vi)
- Click expand → all correct answers + play audio
- Filter chip "Câu yếu của tôi" — questions user got wrong most often (from `n400_question_attempts`)

### 4.7 Streak logic
"1 active day" = complete a session in any mode with ≥5 question interactions:
- Practice / Mock Test: ≥5 questions answered (any answer counts)
- Flashcards: ≥5 cards marked Đã thuộc / Chưa thuộc

On session completion:
- `today` = current date in `America/Chicago`
- If `last_activity_date == today` → no change
- If `last_activity_date == yesterday` → `current_streak += 1`, update `last_activity_date = today`
- If `last_activity_date < yesterday` (≥1 day gap) → reset `current_streak = 1`
- If `current_streak > longest_streak` → update longest

UI:
- Header badge `🔥 X` on every `/n400app/*` page → click for modal
- Dashboard card with progress bar to next milestone
- Toast on streak +1
- Celebration modal at milestones 3/7/14/30/100

Idempotency: use DB transaction with `UPDATE ... WHERE last_activity_date IS DISTINCT FROM today`.

### 4.8 Admin (`/admin/n400`)
- List 128 questions, click to edit
- Edit form: question_en/vi, answers list (add/remove/edit correct + distractors), upload audio
- Tabs for `n400_state_data`, `n400_representatives`, `n400_location_answers` management
- Cache invalidation on save (tag-based revalidation)

## 5. Error Handling & Edge Cases

### 5.1 Geocodio
- Timeout / API down → "Không thể xác định khu vực. Vui lòng kiểm tra lại địa chỉ hoặc thử lại sau." + retry button
- Address not found → block save, ask user to recheck
- Still ambiguous after street address (rare) → save profile with `district_number = null`; Q29 displays "Chưa xác định được đại biểu của bạn. Vui lòng liên hệ admin."
- Rate limit → save profile, mark `district_resolved_at = null`, background retry job

### 5.2 Audio
- File fails to load → 🔊 button disabled with tooltip "Audio đang bảo trì". Quiz continues.
- Browser autoplay blocked (iOS Safari) → Repeat button always visible, user clicks.
- Rapid question advance → stop previous audio before loading next.

### 5.3 Auth
- OAuth provider failure → email login fallback prominent
- Email unverified → redirect `/verify-email`
- Mid-quiz session expiry → save quiz state to localStorage, prompt re-login, resume.

### 5.4 Content gaps
- Missing VI translation → show EN + badge "Bản dịch đang cập nhật"
- < 3 distractors available → fall back to 2-option quiz for that question, log warning
- Missing location data for user's state → exclude that question from quiz pool, log warning
- Q29: missing rep for resolved district → "Chưa có data cho khu vực này, vui lòng liên hệ admin"

### 5.5 Quiz state persistence
- Refresh / close mid-quiz → save state to localStorage on every answer; resume prompt on return
- Browser back mid-quiz → unload prompt
- Mock test only saves to DB on completion (avoid skewing stats)

### 5.6 Multi-device
- Concurrent attempts on different devices → both saved as distinct attempt rows (no conflict)
- Profile edit conflict → last-write-wins

### 5.7 Network / performance
- Slow / offline → Service Worker caches 128 questions + audio after first load. Flashcard + View All work offline. Mock Test requires online (for attempt save).
- First load > 3s → text skeleton "Đang tải câu hỏi..." (no blank spinner)

### 5.8 Low-tech UX safeguards
- Buttons ≥ 48×48px
- Body ≥ 18px, questions ≥ 24px
- Confirm dialog before quitting quiz
- Bilingual error messages, no jargon
- "Trợ giúp" link on every screen

### 5.9 Admin
- Wrong audio format → reject ("Chỉ chấp nhận .mp3, max 500KB")
- Soft-delete questions referenced in attempts (preserve user history)
- Bulk import CSV → transaction rollback on failure with line numbers

## 6. Testing Strategy

### 6.1 Unit tests (critical only)
- Mock test pass/fail algorithm (12-pass / 9-fail / 20-cap)
- Question randomization: no duplicates per quiz, fair distribution
- Distractor selection: 1 correct + 3 distinct distractors, no overlap with other correct answers of same question
- Multi-correct logic: pick 1 random correct to display
- Location lookups: state→senator/governor/capital, district→rep
- Streak transitions: same-day / next-day / gap-day / multi-device idempotency

### 6.2 Integration tests
- Geocodio: mock happy path, timeout, not-found
- Auth → profile gate → setup redirect
- RLS: user A cannot read user B attempts; admin can read all
- Admin edit → cache invalidation → public reflects

### 6.3 E2E (Playwright, scoped)
- Signup → setup (Houston 77083) → dashboard
- Mock test pass golden path → certificate
- Mock test fail path → breakdown
- Flashcard flip + audio play

### 6.4 Skip (YAGNI v1)
- UI presentation tests
- Audio playback browser verification
- Admin UI E2E (manual QA sufficient)

### 6.5 Pre-launch data verification scripts
- Compare DB content vs `docs/N400_questions_en.md` and `N400_questions_vi.md` (count, ordering)
- Every question has ≥1 correct + ≥3 distractors
- Every `question_audio_url` and correct-answer `answer_audio_url` exists in Storage
- All 50 states have senator_1/2, governor, capital populated

### 6.6 Analytics events (GA4 + Meta Pixel)
- `n400_signup_complete`
- `n400_setup_complete`
- `n400_mock_test_start`
- `n400_mock_test_pass` ← high-value retargeting event
- `n400_mock_test_fail`
- `n400_practice_complete`
- `n400_flashcard_session`
- `n400_streak_milestone` (param: streak_count, fires at 3/7/14/30/100)

### 6.7 Monitoring (ties to Track 3 W1)
- Sentry: Geocodio errors, Supabase query failures
- Uptime check on `/n400app`
- CWV alert

## 7. Open Items (must resolve before implementation)

1. **English question source file empty.** `docs/N400_questions_en.md` is 0 lines. User must paste 128 EN questions before audio generation and DB seed can run.
2. **TTS provider choice.** ElevenLabs (highest quality, ~$30 one-time) vs OpenAI TTS (~$15, slightly more robotic). User to pick.
3. **Audio file count.** 128 questions + ~500 correct answers + ~50 governors + ~50 capitals + ~100 senators + ~435 reps. Estimate ~1,300 files total. Generate as one batch via script.
4. **Distractors source.** USCIS only publishes correct answers. Distractors must be authored. Approach: tao generate via AI (similar-format wrong answers within same category), user reviews and edits before launch.
5. **Service Worker scope.** Confirm OK to add SW for `/n400app/*` only (not entire website).

## 9. Implementation Phasing (rough)

This spec describes the full v1. Implementation plan (next step via writing-plans skill) will break into ordered tasks. Rough phasing:

1. **DB schema + seed scripts** (migrations, USCIS content import, distractor authoring)
2. **Audio generation pipeline** (TTS script, Storage upload, URL backfill)
3. **Auth + setup flow** (login wiring, profile gate, Geocodio integration)
4. **Mock Test** (the core feature — quiz engine, render, scoring, certificate)
5. **Daily Practice + Flashcards + View All** (reuse Mock Test components)
6. **Streak system** (DB transitions, UI badges, toasts)
7. **Admin panel** (content CRUD, audio upload, location management)
8. **Analytics + monitoring wiring**
9. **Pre-launch data verification + smoke test**
