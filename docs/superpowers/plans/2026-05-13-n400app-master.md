# N400 Civics Test App — Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each phase plan task-by-task. This master document is overview only — actual tasks live in per-phase plans.

**Goal:** Build a bilingual (EN/VI) civics test practice app at `mannaos.com/n400app` for Vietnamese-American naturalization applicants, with mock test, daily practice, flashcards, and full 128-question browser.

**Architecture:** New routes under `/[locale]/n400app/*` inside existing `apps/website/` Next.js 16 App Router project. Reuses Supabase Auth, i18n, admin pattern from Phase 3. Content + audio in Supabase. Pre-generated TTS audio via Google Cloud TTS. Geocodio for congressional district lookup. Upstash Redis for rate limiting.

**Tech Stack:** Next.js 16.2.4, React 19.2.4, Supabase (Auth + Postgres + Storage), Tailwind CSS 4, Radix UI primitives, Google Cloud Text-to-Speech, Geocodio API, Upstash Redis (via Vercel Marketplace), `@supabase/ssr`.

**Spec:** `docs/superpowers/specs/2026-05-13-n400app-design.md` (v2 approved).

## Implementation Conventions

These apply across all phase plans. Don't repeat them in each phase.

### File location patterns
- Routes: `apps/website/src/app/[locale]/n400app/<route>/page.tsx` (and `layout.tsx` where needed)
- Server actions: `apps/website/src/app/[locale]/n400app/<route>/actions.ts`
- Shared components: `apps/website/src/components/n400/<ComponentName>.tsx`
- Domain logic (pure, testable): `apps/website/src/lib/n400/<module>.ts`
- DB migrations: `apps/website/supabase/migrations/n400_<NN>_<description>.sql`
- Seed scripts: `apps/website/scripts/n400/<name>.ts`
- Tests: co-located as `<module>.test.ts` next to source, OR `apps/website/__tests__/n400/<area>/<name>.test.ts`

### Naming
- Tables, columns, RLS policies: `snake_case`, prefix `n400_`
- TS modules: `kebab-case.ts`
- React components: `PascalCase.tsx`
- Functions: `camelCase`
- Vitest is the test runner (install in Phase 1 first task).

### Auth
- All `/n400app/*` routes EXCEPT `/n400app` landing require auth. Existing middleware (`src/middleware.ts`) enforces auth for `/portal` and `/admin`. Phase 3 will add `/n400app` to the protected list with a special case for the public landing page.

### Cache strategy
- Public content (questions/answers/state data/reps): `revalidate: 3600` + tag `n400-content`. Admin saves call `revalidateTag('n400-content')`.
- User-specific data (attempts, profile): no cache, server-rendered per request.

### i18n
- New translation keys go into `apps/website/src/messages/en.json` and `vi.json` under namespace `n400`. Use existing `getDictionary()` pattern.
- Bilingual labels that are ALWAYS shown together (regardless of locale) are inline strings, not i18n keys. Example: setup form helper text shows EN + VI together.

### Testing strategy
- Unit tests: pure functions (quiz engine, distractor selection, streak transitions, geocoding response parsing)
- Integration tests: server actions with mocked Supabase + Geocodio
- E2E (Playwright): added in Phase 9; smoke paths only

### Commit conventions
- Prefix `feat(n400):`, `fix(n400):`, `test(n400):`, `chore(n400):`, `db(n400):`
- One logical change per commit (per CLAUDE.md atomic commits rule)
- After each task that ends with a passing test, COMMIT before starting the next task
